## 1. Objective

Deliver a lightning-fast expense logging flow engineered for sub-3-second transaction entry. Implement a POS-style integer keypad input that formats keystrokes directly into sen, real-time deduction preview pills showing the post-transaction account balance, a tactile 3-column category matrix, and commitment lock protections for linked recurring transactions.

### 2.1 POS-Style Integer Money Input
- Amount entry field tagged with `testID="money-input"` (retaining `expense-form-amount`).
- Direct integer keystroke mapping: typing `1` $\to$ `RM 0.01`, `1-2` $\to$ `RM 0.12`, `1-2-5` $\to$ `RM 1.25`, `1-2-5-0` $\to$ `RM 12.50`.
- Eliminates decimal cursor jumps and floating point imprecision.
- Large centered hero typography (`text-5xl font-black font-mono tracking-tighter`).

### 2.2 Projected Balance Deduction Preview
- Interactive horizontal chips tagged with `testID="account-pill-{id}"` (retaining `expense-form-account-{id}`).
- Previews real-time financial deduction before submission (e.g., `Maybank: RM 3,450.00 -> RM 3,437.50`).
- Provides immediate visual feedback of remaining liquidity.

### 2.3 Category Matrix & Date Controls
- 3-column asymmetric grid (`testID="category-matrix"`), enforcing minimum 48px touch targets with tactile feedback.
- Remembers last-used category via Zustand (`useUiStore`).
- Quick date selectors: `Today` and `Yesterday` pill toggles, plus standard date picker.

### 2.4 Commitment Lock Badge (Edit Flow)
- For transactions auto-generated by commitments (`expenses/[id]/edit.tsx`):
  - Manual edits and delete triggers are disabled.
  - Tagged with `testID="linked-commitment-lock"` (retaining `linked-expense-view`).
  - Displays explanatory banner: *"This expense is linked to an active recurring commitment. Manage or reverse this transaction from the Commitments tab."*

## 4. Invariants & Guardrails

- **Zero Floating-Point Representation**: Keystroke accumulation works directly on integers (`amount_sen`).
- **Domain Balances**: Deduction calculation applies exact asset vs credit card balance semantics.
- **Double-Submit Protection**: Save action button disables while transaction is in-flight.
